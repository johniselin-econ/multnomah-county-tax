# CLAUDE.md — orientation for agents working in this repo

First time here? Read this, then `README.md` (human replication guide),
`RUNBOOK.md` (SLURM/cluster), and `STATA_REQUIREMENTS.txt` (packages). This file
is the high-signal operating guide; the others have the detail.

## What this is

Replication code for **Conway, Iselin & Rork (2026)**, *"Mult-No-More?"* — the
migration effects of Multnomah County's Preschool-for-All income tax (enacted
2020, effective 2021). Methods: **Synthetic DiD (primary)**, PPML gravity flows,
individual-level DiD, specification curves, and a TAXSIM revenue microsimulation.

## Pipeline — three stages, run from the repo root

1. **`00_download_data.R`** — R data pulls (IPUMS ACS, NHGIS, BLS, DOL, Census).
2. **`00_multnomah.do`** — Stata orchestrator: cleaning (`01_*`) → analysis (`02_*`).
3. **`00_post_stata.R`** — R diagrams + maps (needs Stata's `acs_county_sample.xlsx`).

Stata reads R-produced inputs, so the order matters. The `run_stage1.sh` /
`run_stage3.sh` wrappers just add env checks around the two R entry points.

## Layout

- `code/stata/` — pipeline do-files: `01_clean_data.do` (calls `01b–01h`),
  then `02_*` analysis (`sdid`, `did`, `flow`, `revenue_microsim`, `post_spec`,
  `bootstrap`, `tables_figures`, diagnostics, appendix).
- `code/utils/globals.do` — **single source of truth for Stata settings**: paths,
  parameters, master seed, the required-package check, output dirs, and Overleaf
  resolution. Every entry script reaches it via a small locator preamble, and it
  sources `programs.do` at the end — so sourcing globals yields paths + params +
  all programs in one step.
- `code/utils/programs.do` — all reusable Stata programs, incl. the `project_*`
  manifest/seed/preferred-spec helpers.
- `code/R/` — R scripts; `multnomah_r_common.R` holds the orchestration helpers
  (`multnomah_r_init` + the stage run-functions) the entry scripts call.
- `resources/` — config inputs. `narrow_pool_fips.csv` is the source of truth for
  the narrow donor pool (edit the CSV, not Stata code); `paper_manifest.csv` feeds
  the audit script.
- `data/` — inputs (mostly gitignored; a few small/hard-to-reproduce files tracked).
- `results/` — all outputs (gitignored, regenerated by code).

## Local configuration

- Stata run knobs live in the **RUN-CONTROL FLAGS** panel at the top of
  `00_multnomah.do` (`run_bootstrap`, `bootstrap_reps`, `use_parallel`,
  `n_clusters`, `resume`, `event_study_mode`). `globals.do` supplies the same
  defaults for scripts run standalone.
- Overleaf sync (optional): copy `user_settings.example.{do,R}` →
  `user_settings.{do,R}` (gitignored) and set `oth_path`. No file ⇒ no sync.

## Conventions — follow these

- **Stata ↔ R parity.** R mirrors Stata. When you change one, change the other and
  keep the spec identical (sample restrictions, fixed effects, clustering,
  variable definitions). Document any intentional deviation.
- **Naming.** `snake_case`; pipeline numeric prefixes (`00_` orchestrator, `01_`
  clean, `02_` analysis). **Never** name a main/orchestrator script `master`.
- **Plan before non-trivial work.** Multi-file changes, new specs, or
  Stata↔R translations: outline the plan first, then implement.
- **Verify, then report.** Don't claim a run succeeded without checking outputs;
  report failures with the actual error.

## Reproducibility invariant

`project_export_run_manifest` writes `results/run_manifest_latest.csv` with a
`config_signature` built from the seed, year windows, and run flags. **Master seed
= 56403.** A pure refactor must leave the signature byte-identical; a deliberate
spec change should change it on purpose. Use this as the regression gate after any
setup/plumbing edit.

## Gotchas

- **Windows + `core.autocrlf=true`.** Working tree is CRLF, repo stores LF (git
  hides the difference). Write files with LF. Branch switches occasionally hit a
  OneDrive/AV file lock (`unlink … Invalid argument`); if a `checkout`/`reset` is
  blocked, move refs with plumbing (`update-ref` + mixed `reset`) instead of
  rewriting the working tree.
- **A full run is multi-day** (the 500-rep publication bootstrap dominates). Don't
  launch a second Stata-MP instance while one is running (license + CPU
  oversubscription).
- **The user edits files externally** — re-read before editing.
- Bootstrap inference is a **donor-cluster bootstrap** (resamples the donor pool,
  Multnomah fixed); CIs are reported only for the Table-2 elasticities, not the
  revenue numbers. SDID point inference uses the placebo method (single treated
  unit). See Appendix C of the paper.
